## 为什么会堆出来（根因，不是"测具设计"）

`tools/ui_snapshot.cpp` 里输出目录的默认值曾是硬编码的 `C:/Users/yyyy/idm_shots`；
再加上"每轮临时传一个新的 `IDM_SHOT_DIR`、顺手 `tee` 一份构建日志到主目录根"的习惯，
从 09-11 到 09-29 攒出 **47 个条目 / 191.5MB**。已改：

1. 默认目录 → `%TEMP%/idm-next-probes/<当天日期>`（单一子目录 + 轮次日期）；
2. 新增守卫：`IDM_SHOT_DIR` 若直接落在用户主目录根（`~/idm*` 这种第一层）⇒ **拒写并返回 2**
   —— 约定会被忘记，所以写成断言；
3. CI 的产物目录统一到同一个约定（`.github/workflows/ci.yml`）；
4. 仓库内备选位置 `build-probes/` 已加进 `.gitignore`。

实测守卫（两条都跑过）：
```
IDM_SHOT_DIR="C:/Users/yyyy/idm_shots_new" ./build/ui_snapshot.exe
  → rc=2  "IDM_SHOT_DIR 拒绝写进用户主目录根：C:/Users/yyyy/idm_shots_new"
（不传 IDM_SHOT_DIR）./build/ui_snapshot.exe
  → rc=0  [out] 产物目录 = %TEMP%\idm-next-probes\2026-09-29
```

### 判读

* **没有任何两个目录逐字节相同** ⇒ 这不是"改个名字重复渲染"的副本，
  按名字（`v2`…`v8`）判重会误删。
* 与当前代码最接近的是 **`idm_shots`**（同名 14 / 逐字节同 6），其次 `idm_ui_v8`（11/3）。
  ⇒ 保留候选 = `idm_shots`；其余（`idm_ui_v2..v8`、`idm_shots2/dark/dark2/dbg/dbg2`、
  `idm_ui_dark/light`）归入**待你拍定后处理**。
* 删错的代价写清楚：`idm_ui_v2..v8` 的 mtime 全在 2026-09-14 08:38–09:00，
  正是那轮 UI 迭代的逐版本快照；截图从不入 git，所以它们很可能是那条迭代路径
  **仅存的证据**，删掉后无法从任何地方重建。
* "同名但字节不同"不等于界面变了：本仓库早有记录，同一份代码连跑两次部分面板也有噪声差异。
  判断"哪一套对应当前代码"应以**同名数**为主，不是逐字节数。
* 表一里 `idm_shots` 的"仅文档/注释提及"指 `ui_snapshot.cpp` 里一句历史说明
  （"真实 tasks.json 里 117 条全是 ui-shots/idm_shots 下的假任务"），
