# UI-01 · TaskUI 设计决策与约束
基线：`9d21a4357eaf6fa57f19e53f50c37ca3c7e9e9ea`；资料来源：资料库 TaskUI-v1.0.0.zip（SHA-256 `51a3d064487ba0254282e5c48e6215b5486f9884cdfa3b74a20b1285536d164c`），原样 vendored 为 `TaskUI/`，`docs/taskui/SHA256SUMS` 记录逐文件校验值。

## G0 对象与角色
- 核心对象：**下载任务**（ID、来源、保存路径、状态、进度、错误、可能的队列）、**网页资源**（URL、类型、名称、大小、源标签页）、**转交请求**（UUID、已接收/待确认身份）、**连接状态**（Host/GUI/未知）。
- 角色：普通用户想“一键发现并下载”；专业用户需要筛选、批量操作、详情诊断。频率判断目前只是 **假设**，需 G3 访谈/操作数据验证。
- 主要风险：未知 ACK 重复提交、插件取消浏览器原下载、错误覆盖本地文件、配置操作侵入 Windows 注册表。当前阶段不改变这些行为。

## G1 入口归属（功能不能堆积为新页面）
1. **下载任务**：桌面主表+上下文菜单；新建唯一首要工具栏入口；详情按需弹出。保留现有 Qt6 工具栏已经收敛的成果。
2. **资源发现**：浏览器 Popup 主区维持资源列表；逐项操作就地；批量操作集中在底栏，搜索、类型过滤就地。
3. **最近转交/浏览器下载**：低频或情境性信息按需显示；不再强迫两个次区域长期常驻；如何折叠必须经 UI 实测。
4. **连接诊断**：从断连状态进入**同 Popup 局部向导**；不新增客户端永久侧栏，也不重新建立单独复杂页面。
5. **专业设置**：保留设置层；路径/格式/高级选项按需显示，而不干扰资源列表。
6. **键盘与无障碍**：既有 Ctrl+N（桌面）与 /（扩展搜索）要保留；单资源 Enter 操作只是 G2 目标，尚未实现。其它快捷键需避免破坏已有页面行为。

## 产品设计原则（高于视觉布局）
- **主路径完整**：浏览器发现资源 → 选择资源 → 桌面确认接收 → 跟踪状态 → 成功后找到文件；每个转换必须有可信证据及下一步动作。
- **意图一致**：点击“选择目录/画质”不能在无法弹出配置卡片时直接改为提交下载。必须返回明确的“无法配置”状态，提供用户确认后才允许退化。
- **批量身份诚实**：仅收到 `success=2,failed=1` 这样的聚合数量时，不能推测哪两个具体对象成功；不得将列表前 N 个伪标记为已发送、不得清除失败/未知任务对应的选择。
- **状态与能力边界**：发现、准备提交、已接收、进行中、暂停、已完成、失败、结果未知及被浏览器接管是不同状态；展示以明确可信证据为准，未实测功能不声明已实现。
- **用户分层**：首次使用者快速发现文件与下载；专业用户能查明队列、速度、协议、存储目录、失败原因；高级能力不阻挡主路径。
- **错误恢复优于报错数量**：用户能知道“发生什么/有什么影响/现在能做什么”，避免堆叠原始 IPC 错误和泛化 toast。
- **安全胜过自动化**：不自动重发未知 UUID，不自动取消用户浏览器下载，不静默改注册表，不隐式覆盖现有文件。

## 交互状态与恢复规则
- `资源已发现` ≠ `桌面已接收任务` ≠ `文件下载完成`；状态字面明确、颜色不能成为唯一线索。
- 所有修改操作定义 loading/success/failure；**未知 ACK 明确 UNKNOWN**，不提供静默重试。Native 消息、UUID 状态存储逻辑由独立可靠性 PR 管理。
- 连接诊断默认只读；注册脚本与会更改 Windows 的操作必须用户主动确认和执行。
- 高风险取消、删除、覆盖必须通过单独代码及实际路径验证，不在 UI-01 声称已有通用撤销。

## 比例与技术
- Manifest 中 0.63 / 0.58 / 0.70 为**设计意图**（桌面任务列表/Popup 资源列表/诊断步骤），不是像素实测。
- Fluent 2 仅作视觉参考，保持 Qt6 QSS + HTML/CSS 现有技术栈；沿用现有配色 Token 与 6–8px 圆角，不迁移 WinUI。
- 不引入仪表盘式首页、巨型卡片、玻璃拟态、独立协议导航页或重写引擎。
