# UI-01 · IDM Next 跨端任务状态与用户反馈契约（G1 设计，未实施）
目的：统一“扩展资源 → Native Host → GUI 下载任务 → 本地文件”的对象身份、用户预期和失败恢复。此文件是未来 G2 的验收合同，不是现有运行协议已支持的功能。

## 一、区分对象与状态（绝不可混为一谈）
| 层 | 对象主键 | 状态 | 用户文案 | 可以证明什么 |
| --- | --- | --- | --- | --- |
| 浏览器资源 | tabId + URL（当前实现常用 URL 去重） | discovered | 找到资源 | 浏览器观测到一个可疑资源地址，不证明可下载 |
| 发起意图 | action + URL + opts | configuring/ready | 正在设置下载选项 | 选择了路径、画质等，但还**未发送** |
| 原始 Native 请求 | request UUID | pending/unknown/reconciled | 请求中 / 结果待确认 / 身份已核对 | 防止重复提交；unknown 时不得自动重投 |
| 桌面任务 | taskId + sessionId | accepted/queued/downloading/paused/failed/completed | 已接收/等待/下载中/已暂停/失败/已完成 | 桌面任务生命周期，不等于用户已打开文件 |
| 本地文件 | 完成的文件路径 + 文件存在证据 | available/unknown/error | 已保存（可打开）/文件状态未知 | 用户最终目标，须实际核查后才能展示“已保存” |

## 二、操作状态机（目标）
```text
资源发现 → 选择资源 → [可选：配置文件名、保存位置、画质]
                   ↓ “提交下载” 明确动作
                请求发出
            ┌──────┼────────┐
      明确拒绝   ACK 未知     明确接收(taskId/sessionId)
         ↓         ↓               ↓
       错误说明  留存UUID→只读核对    任务已接收
                 │                  ↓
               仍未知          队列/下载/失败/完成
                 │                  ↓
          不重投/人工核查      文件位置可查/打开
```
- **用户请求“选择保存目录/画质”时，不能越级进入“提交下载”**。当前页面配置卡片不可用必须有明确提示；只有用户另行点击“直接下载”才执行。
- **Native Host 失败 vs GUI 未运行 vs 扩展无权限** 的诊断级别必须来自实际可观测证据；`ping` 只说明特定连接检查成功/失败，不能凭一个布尔值推断唯一根因。
- **批量不确定时不伪造条目身份**：如果协议只返回 `success=2,failed=1`，展示“已接收2项、失败1项、具体条目未知”，不向任何资源行写具体“已发送”。UI 保留选择上下文，不静默重发。后续若要细分结果，Native 协议必须提供逐任务身份或只读核对机制，单独验收。
- **重复下载保护优先于“重试一切”**：未知 UUID 和既有浏览器原下载可能仍成功，绝不把超时等同未接收。

## 三、必须覆盖的用户感知状态
| 场景 | loading | empty | success | partial/unknown | failure / next action |
| --- | --- | --- | --- | --- | --- |
| 网页资源发现 | 正在扫描（能取消/正常继续浏览） | 尚未发现资源 + 可行动提示 | 显示 URL 类型/可用字段 | 不明类型标未知，不编造大小/清晰度 | 不支持页面/权限不足显示原理及换页方案 |
| 单条提交 | 请求正在提交，防重复 | 不适用 | “桌面已接收”，随后提供任务查询 | “结果待确认，勿重复提交” + 只读核对 | 明确拒绝 → 安全返回选择 |
| 批量提交 | N 个待提交，禁止连点 | 未选择时明确“全部/选择集”范围 | 每条身份可核对时才做逐条成功标记 | 聚合计数、明细未知必须单独显示 | 失败数量/原因/保留选择上下文 |
| 连接诊断 | 检测中 | 无证据写未知 | 已验证能够连接 | Host/GUI 诊断不明确标未知 | 下一步操作、重查、复制脱敏诊断 |
| 桌面下载任务 | 排队/下载中进度有来源 | 空任务列表引导新建 | 引擎已完成后核对文件 | 文件路径/磁盘状态未知时不说“已保存” | 错误详情 + 重试或安全回退 |

## 四、设计验收不可妥协的示例
1. 以三资源的 batchAdd 返回聚合 `success=2,failed=1`：**不能**将 `list[0:2]` 标记为成功；全批状态应为“部分接收”。
2. 在支持 HTML Popup 但 content script 不能打开配置卡片的页面，点击“选择路径”：**不得**发送 `add_download`。
3. Native ACK 丢失/Worker 被终止时：原 request UUID 可只读核对，但不能发起新的 add。
4. 普通用户点击“检查连接”：显示诊断证据和手动修复建议，不执行注册脚本/修改注册表。
5. Qt6 桌面完成任务后：用户能找到文件，失败时能定位原因；状态及操作在暗/亮色与键盘下可识别。
6. Popup 无资源、有 3 个资源、200 个资源、浏览器下载候选和转交记录同时展开时，主列表仍可使用；具体阈值按真实视口证据确定。
