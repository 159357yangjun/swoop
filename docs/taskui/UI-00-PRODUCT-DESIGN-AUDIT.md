## 二、产品设计问题（G0/G1 决策，而非代码质量问题）
1. **没有统一的“用户目标闭环”**：资源发现 → 选择（含保存位置/画质）→ 接收确认 → 下载执行 → 结果/保存文件定位，必须定义跨扩展和桌面端可追踪的身份与信息；目前单条/批量路径的可核验程度不同。
2. **新手与高级需求混杂的风险**：不能只把功能“全部折叠到更多”，也不能把专业设置铺满主区。新手目标是下载成功并找到文件；高级用户需要队列、连接、限速、分片和日志。
3. **同一操作多个入口的行为差异**：双击/底栏/右键/选择目录卡片必须对齐结果契约；`UX03` 是操作意图失配的确定性代码证据。
4. **系统的“成功”不等于用户的成功**：Native ACK、收到任务 ID、磁盘写入完成、用户能打开文件是四个不同阶段，不能使用同一个绿色成功态。
5. **安全的失败模式不等于有用的失败体验**：保持未知 UUID 不重试是正确的底线，但还需要可理解的说明、上下文保留和明确的人工核查路径。
6. **商业定位需要被真实平台验证**：不能以“全协议”宣传推导出任何视频网站均兼容；分清受支持资源、允许公开下载、DRM/签名鉴权限制和未知兼容性。
