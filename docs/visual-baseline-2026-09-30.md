## ① 先回答"一屏里最重要的一件事是什么"

**是任务列表，不是"当前传输"。** 理由不是审美：这个产品的核心动作是"我下的那 8 个里现在哪个在动、
哪个卡住、哪个完了"，而"当前传输"只是列表的**一个筛选视图**。现状也确实把总速度放在状态栏右侧
（`0 B/s`）+ 左侧计数行（`下载中 0 · 已完成 0 · 失败 0`），主窗中央整块给列表 —— 方向是对的。
所以本轮**不**为"当前传输"另立主角（那会把 1077px 宽的列表挤成侧栏），
要改的是列表自身的可读性与达标线。

| | 白字对比（要求 4.5） | 对窗体底 `#18191c`（非文本要求 3.0） |

非文本对比 3.74 也还留有余量。这条改动会动到 `IDM_*` 探针里量像素的断言吗 ——
`IDM_FILEICON_PROBE` 的 [3] 比的是"同一张表装委托 vs 控制表格"，两边同主题同令牌，不受影响；
但**换色之后必须重跑并重新登记改前/改后哈希**，不能拿本表旧值当基线。

## 这份表没覆盖的（不装作覆盖了）

1. 托盘菜单、失败行、键盘焦点三处**没有图**，所以那三项的打分是"未验"，不是"通过"。
2. 对比度只算了"同一选择器里前景与背景都写死"的 23/22 组 + 手挑的正文/按钮配对；
   自绘控件（进度条、状态徽章、图标）的颜色不在 QSS 里，得从 `app_icons.cpp`/`progress_delegate.cpp`
   取常量再算，本轮没做。
3. 间距/圆角的"40 处非阶梯值"是**条数**，不是"每处都该改"：1px/2px 这类描边级微调可能是刻意的，
   要逐处判断得配合截图圈点，本轮没做这个判断。
