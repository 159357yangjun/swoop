# 「不变」断言必须配一个「必变」夹具

规则一句话：**任何形如「改前 == 改后」「与旧通路逐像素相同」的断言，单独存在时没有证据价值。**
它只能证明"世界没动"；当两侧同时变坏，它是结构性地瞎的 —— 因为它拿自己当对照。

实测案例（2026-09-30，`IDM_FILEICON_PROBE`）：把 `src/gui/app_icons.cpp` 里
`case FileType::Compressed:` 注掉之后，

- `[PASS] 装了生产委托的单元格与改前通路逐像素相同` ← **照样绿**
- `[FAIL] 六个取值的图标两两不同` ← 只有这条报了

原因：前一条的"控制表格"是拿 `AppIcons::fileTypeIcon(...)` 现造的，用的就是那张坏掉的表；
两侧一起变，差值为零。所以对照式断言必须配一个**已知会红的夹具**（与 PicList 的
`red-demo` / `mutate` 同一口径）：注进实现里它必须红，拔了就绿。

## 现成夹具与可重跑命令

夹具：`src/gui/app_icons.cpp` 的 `fileTypeIcon()` switch 少一个 `case`（天然的"静默降级"样本）。
配套断言：`IDM_FILEICON_PROBE` 第 [7] 条（六个取值两两不同）。

```
bash tools/mutation_fixture_fileicon.sh          # 全程自动：注→建→跑→拔→核对还原
```

脚本自己做四件事，任何一步不满足就非 0 退出：
1. 记录改前 `git diff --numstat`；
2. 注掉那个 `case`（先 `assert` 改动真的落到磁盘上，防"空操作却报成功"）；
3. 重新构建并**要求输出里出现对应的 `Building CXX object .../app_icons.cpp.obj` 行**
   （没有这行就是没重编，跑的是旧二进制，结果不记账），然后跑探针，
   **要求 `[7]` 报 FAIL**；
4. 还原并核对 `git diff --numstat` 与第 1 步逐字一致，不一致就红着退出。

## 写新断言时的自检问句

对着这条断言问："**把我要护的那行删掉，哪一条会红？**" 答不出具体那条，就是它在冒充。
再问一句："这条断言的对照组，是不是也用被测的那段代码算出来的？" 是 → 它必须配夹具。
